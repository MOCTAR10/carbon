Prérequis — Ce qu'il vous faut
Avant de commencer, vérifiez que vous avez tout ça
  • Accès SSH à votre serveur 37.60.240.199 (utilisateur root ou sudo)
  • Le code de l'application (dossier carbon-app/)
  • Un client SSH : PuTTY (Windows) ou Terminal (Mac/Linux)
  • Un client SFTP : FileZilla ou WinSCP (pour uploader les fichiers)
  • Votre mot de passe ou clé SSH du serveur
📌

Vérifiez d'abord le système de votre serveur : Ce guide est pour Ubuntu 20.04/22.04 ou Debian 11/12. Si vous avez CentOS/Rocky, les commandes apt diffèrent.

1
Connexion SSH au Serveur
Se connecter à votre VPS depuis votre PC

Ouvrez un terminal (ou PuTTY sur Windows) et tapez :

ssh root@37.60.240.199

Entrez votre mot de passe quand demandé. Vous verrez quelque chose comme :

# Welcome to Ubuntu 22.04.3 LTS
root@vps-xxxxx:~#
⚠️

Si vous n'êtes pas root : connectez-vous avec votre utilisateur normal, puis tapez sudo -i pour passer root. Toutes les commandes ci-dessous s'exécutent en tant que root.

Mettre à jour le serveur

Toujours commencer par mettre à jour :

apt update && apt upgrade -y
2
Installation de Node.js 20 LTS
Le moteur qui fait tourner votre application Next.js
ℹ️

Vous utilisez peut-être déjà une autre version de Node.js sur le serveur pour d'autres apps. Ne vous inquiétez pas — nvm gère plusieurs versions en parallèle sans conflit.

Option A — Via NodeSource (plus simple, recommandée)

# Télécharger le script d'installation Node.js 20
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -

# Installer Node.js
apt install -y nodejs

# Vérifier l'installation
node -v # doit afficher v20.x.x
npm -v # doit afficher 10.x.x

Installer PM2 (gestionnaire de processus)

PM2 garde votre app en vie 24h/24, la redémarre si elle plante, et la relance après un reboot.

npm install -g pm2

# Vérifier
pm2 -v
3
Installation & Configuration de PostgreSQL
La base de données de CarbonTrack

Installer PostgreSQL

apt install -y postgresql postgresql-contrib

# Vérifier qu'il tourne
systemctl status postgresql
💡

Si une autre app utilise déjà PostgreSQL sur ce serveur, c'est parfait — vous allez juste créer une nouvelle base de données et un nouvel utilisateur dédié à CarbonTrack. Aucun conflit possible.

Créer la base de données et l'utilisateur

# Se connecter à PostgreSQL
sudo -u postgres psql

Vous êtes maintenant dans la console PostgreSQL postgres=#. Tapez exactement :

-- Créer un utilisateur dédié (changez le mot de passe !)
CREATE USER carbontrack_user WITH PASSWORD 'MonMotDePasseSecurise2026!';

-- Créer la base de données
CREATE DATABASE carbontrack OWNER carbontrack_user;

-- Donner tous les droits
GRANT ALL PRIVILEGES ON DATABASE carbontrack TO carbontrack_user;

-- Quitter PostgreSQL
\q
⚠️

Remplacez MonMotDePasseSecurise2026! par un vrai mot de passe fort. Notez-le bien — vous en aurez besoin à l'Étape 5.

Initialiser le schéma (créer les tables)

# On fera ça après avoir uploadé les fichiers (Étape 4)
# La commande sera : psql -U carbontrack_user -d carbontrack -f /var/www/carbontrack/scripts/init-db.sql

5
Créer le Fichier de Configuration (.env.production)
Les variables secrètes de votre application
🚨

Ne jamais committer ce fichier sur GitHub ! Il contient vos mots de passe. Il doit rester uniquement sur le serveur.

Créer le fichier

nano /var/www/carbontrack/.env.production

Copiez-collez ce contenu (et remplissez les valeurs) :

📄 /var/www/carbontrack/.env.production
# ═══════════════════════════════════════
# CarbonTrack — Variables de Production
# ═══════════════════════════════════════

# Environnement
NODE_ENV=production

# Base de données PostgreSQL
PGHOST=localhost
PGPORT=5432
PGUSER=carbontrack_user
PGPASSWORD=MonMotDePasseSecurise2026!
PGDATABASE=carbontrack

# Sécurité JWT (clé secrète — générez une valeur unique !)
JWT_SECRET=remplacez_par_une_longue_chaine_aleatoire_minimum_32_caracteres

# URL publique de l'app
NEXTAUTH_URL=http://37.60.240.199:3001
NEXT_PUBLIC_APP_URL=http://37.60.240.199:3001

Dans nano : Ctrl+O pour sauvegarder → Entrée → Ctrl+X pour quitter.

Générer une clé JWT sécurisée

# Générer une clé aléatoire forte (copiez le résultat dans JWT_SECRET)
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"

Protéger le fichier

# Rendre le fichier lisible uniquement par root
chmod 600 /var/www/carbontrack/.env.production

Garder CarbonTrack en vie 24h/24 sur le port 3001
cd /var/www/carbontrack

# Lancer l'app sur le port 3001 avec le nom "carbontrack"
pm2 start npm --name "carbontrack" -- start -- --port 3001

Configurer les variables d'environnement pour PM2

# Arrêter l'instance actuelle
pm2 stop carbontrack
pm2 delete carbontrack

# Relancer avec le fichier .env.production
pm2 start npm --name "carbontrack" \
--env-file /var/www/carbontrack/.env.production \
-- start -- --port 3001
💡

Si --env-file ne fonctionne pas (ancienne version PM2), utilisez cette méthode alternative :

# Alternative : créer un fichier ecosystem.config.js
cat > /var/www/carbontrack/ecosystem.config.js << 'EOF'
module.exports = {
apps: [{
name: 'carbontrack',
script: 'npm',
args: 'start',
cwd: '/var/www/carbontrack',
env_production: {
NODE_ENV: 'production',
PORT: 3001
}
}]
}
EOF

# Charger les variables puis lancer
export $(cat /var/www/carbontrack/.env.production | xargs)
pm2 start ecosystem.config.js --env production

Configurer Nginx (Proxy + Port 80)
Exposer CarbonTrack sur http://37.60.240.199 sans toucher aux autres apps

Installer Nginx si pas déjà installé

apt install -y nginx
systemctl enable nginx
systemctl start nginx
🔀

Isolation des apps : Chaque application a son propre fichier dans /etc/nginx/sites-available/. CarbonTrack aura carbontrack.conf. Les autres apps ne sont pas modifiées.

Créer la configuration Nginx de CarbonTrack

nano /etc/nginx/sites-available/carbontrack.conf

Copiez-collez cette configuration :

📄 /etc/nginx/sites-available/carbontrack.conf
# ─── CarbonTrack — Nginx Config ──────────────────────────────
# App tourne sur port 3001, Nginx proxy sur port 80

server {
    listen 3001;
    server_name 37.60.240.199;

    # Logs dédiés à CarbonTrack (n'interfèrent pas avec autres apps)
    access_log /var/log/nginx/carbontrack_access.log;
    error_log /var/log/nginx/carbontrack_error.log;

    # Taille max des uploads (documents de certification)
    client_max_body_size 20M;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_cache_bypass $http_upgrade;
    }
}
💡

Explication : Le bloc listen 3001 veut dire que Nginx écoute sur le port 3001 et route vers votre app Next.js (qui tourne aussi sur 3001). Votre app sera accessible à http://37.60.240.199:3001. Les autres apps sur le port 80 ne sont pas touchées.

Activer la configuration

# Créer le lien symbolique pour activer
ln -s /etc/nginx/sites-available/carbontrack.conf /etc/nginx/sites-enabled/

# Tester la configuration (IMPORTANT avant de recharger)
nginx -t
# Doit afficher : syntax is ok / test is successful

# Recharger Nginx (sans couper les autres apps)
systemctl reload nginx

Ouvrir le port dans le pare-feu

# Autoriser le port 3001 dans UFW
ufw allow 3001/tcp
ufw allow 80/tcp
ufw allow 22/tcp # IMPORTANT : garder SSH ouvert !
ufw enable
ufw status

Problèmes Courants & Solutions
Si quelque chose ne marche pas
ErreurCauseSolution
502 Bad Gateway PM2 ne tourne pas ou app plantée pm2 status → pm2 restart carbontrack
Connection refused :3001 Port fermé par pare-feu ufw allow 3001/tcp
ECONNREFUSED postgres Mauvais mot de passe DB ou service arrêté Vérifier .env.production + systemctl start postgresql
Build out of memory RAM insuffisante export NODE_OPTIONS=--max-old-space-size=2048
JWT invalid token JWT_SECRET non défini en prod Vérifier que JWT_SECRET est dans .env.production et chargé par PM2
nginx: [emerg] bind() failed Port déjà utilisé par autre app Changer le port dans carbontrack.conf et dans PM2
Permission denied (publickey) SSH avec clé refusé Utiliser ssh -o PreferredAuthentications=password root@37.60.240.199
